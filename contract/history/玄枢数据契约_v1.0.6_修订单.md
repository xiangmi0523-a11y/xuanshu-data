## 一、§2.3 Variant（异文）：异文独立成模型，不再作证据角色

**原文（§2.3 Variant 条末）：** “……类型码稳定，旧类型码不删除、不改义【用户裁决 A-10；架构验收 3.6】。”

**改为（在原文后追加）：**

> 异文本身的字段（E2-FIX A-5）：两侧读法 reading\_a / reading\_b（增删类一侧可空，两侧不得同时为空）；首选读法 preferred\_reading（a / b；空 = 未判定），非空时必须写 preferred\_basis（判定依据与判定人）；影响等级 impact\_level（none / wording\_only / calculation，必须）与 impact\_note（可选）；版本与出处即 edition\_a / edition\_b 与 passage\_a / passage\_b。impact\_level = calculation 的异文必须关联至少一个受影响的 RuleComponent（发布校验）。异文登记所引用的证据记在 text\_variant\_evidence（variant\_id, evidence\_id），**不得**作为 evidence\_link 的角色登记，也不得充当任何主张的支持。
>
> 迁移：v1.0 中 evidence\_role = 异文记录 的链接改为一条 text\_variant 登记加 text\_variant\_evidence 引用；原 Evidence 行保留（审计链）。截至本修订，正式库无任何正式数据，迁移只涉及 E2 隔离库结构与测试夹具。

## 二、§2.5 evidence\_link：证据链接到可独立评价的具体主张；角色只剩支持 / 反证

**原文：**

> - **evidence\_link：** Evidence ↔ RuleComponent（而非只到 Rule），带 branch\_id。个人证据即使链到正式子项，正式判定时一律不计入。

**改为：**

> - **claim（主张）：** 可独立评价的具体命题，挂在 RuleComponent 下（claim\_id、component\_id、statement 必须）。condition（可选）写命题成立的条件句；一般例外与成立条件写在这里，不得写成反证。不同流派的说法登记为各自独立的主张（有争议时另在 dispute / dispute\_claim 登记），不得用反证表达。正式主张 branch\_id 为空。
> - **evidence\_link：** Evidence ↔ claim（而非整条子项），每个（证据, 主张）对一行。directness（direct / indirect，必须）：直接证据不经推理即可单独说明该主张，间接证据须与其他证据结合推理；直接 / 间接与支持 / 反证是两个独立维度。scope\_note（可选）：该证据对该主张起作用的适用范围（版本、时段、地域等）。证据可信度一律用 Evidence.confidence（§2.4），不在链接上另记。
> - **evidence\_link\_role：** 一条链接可有一个或多个论证角色，各附 role\_note（必须，写明该角色针对的具体内容）。角色只有两值：
>   - **支持：** 该证据为此一主张成立提供理由。
>   - **反证：** 该证据针对此一具体主张，主张其不成立，或攻击其所依据的前提。一般例外、成立条件（→ claim.condition）、流派差异（→ 独立主张）、可信度不足（→ confidence）、未找到（→ search\_record）都不是反证。
>   同一证据对不同主张可以有不同角色；对同一主张可同时具有支持与反证（各附说明）。链接必须至少有一个角色（发布校验）。
> - **不设角色值、按业务含义登记的五类：** 缺席检索 → search\_record（claim\_id、search\_scope、search\_terms、searched\_at、expected\_find\_premise、outcome = 未找到 / 找到，均必须；outcome\_note 可选）；引用行为 → citation\_record（citation\_id、passage\_id、cited\_ref、verdict = 属实 / 不属实 / 未核验，均必须；basis\_evidence\_id、note 可选；只评价引用行为本身，不改变被引主张的状态）；方法论与校准 → Evidence.verification\_method 与 manual\_check\_record（§2.4、§12.2）；权威背书 → 作为“某权威持某说”这一独立主张的证据登记，审查意见入 ReviewRecord（§8.1）；版本源流 → Edition.parent\_edition\_id / base\_text（§2.2）。这五类都不进 evidence\_link，不能充当支持或反证。
> - **个人证据：** personal\_evidence\_link / personal\_evidence\_link\_role 与正式表同构，带 branch\_id；链到正式主张用三元组（claim\_release, claim\_id, claim\_hash）。claim\_hash 的计算对象【待定】（与 v1.0 中个人链接的 component\_hash 同一状态）。个人证据即使链到正式主张，正式判定时一律不计入。

## 三、§7.3 R-I-4

**原文：**

> | R-I-4 | Evidence → RuleVariant | 支持性证据为 NON\_FORMAL ⇒ 变体不得为 FORMAL；反证/限定/异文记录不触发；evidence\_role 枚举须固定 |

**改为：**

> | R-I-4 | Evidence → RuleVariant | 某证据对某变体所属子项下的任一主张具有“支持”角色，且该证据为 NON\_FORMAL ⇒ 该变体不得为 FORMAL。只要有一个真实的支持角色即触发，即使同一证据对同一主张还兼有反证角色。只有反证角色的证据不触发；异文（text\_variant\_evidence）、检索记录（search\_record）、引用行为记录（citation\_record）与证据可信度（confidence）不是角色，不能充当支持，也不触发。角色枚举固定为 支持 / 反证 |
