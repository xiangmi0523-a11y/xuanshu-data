## R1　事务授权绑定

**审核意见：** 放行条件未验证当前事务与授权事务一致；须绑定档案、授权序号、审计 ID；事务结束、提交、回滚、异常退出后立即撤销授权。

**修改位置：** 第 3.6 节第 (1)、(2)、(3) 条（重写）；第 (6) 条触发器条件改写；第 4.2 节新增 U20；第 5.9 节新增测试；第 11 节隔离检查。

**修改内容：**

1. **授权状态：** 删除授权 G 记录 armed、profile_id、grant_seq、audit_id、txn_token。txn_token 为每次 `BEGIN IMMEDIATE` 后新生成的 128 位随机数，只存于闭包。
2. **事务标记：** 同一事务内向 U20 deletion_txn_marker 写唯一一行 (txn_token, audit_id, grant_seq, kind)。
   - 回滚即消失；提交前在同一事务内删除。
   - U20 不是授权依据，写入者不知道闭包中的 txn_token。
3. **逐项比对：** xs_del_gate 与 xs_del_gc 由触发器传入 U20 的 txn_token、audit_id、grant_seq，逐项与闭包比对。
   - 另须 `db.isTransaction` 为真；
   - xs_del_gate 另比对档案；
   - 任一不符或函数内异常，一律返回 0。
4. **撤销时机：**
   - 事务只经 begin()、commit()、rollback() 三个包装函数开启与结束；commit() 与 rollback() 都先撤销授权，再结束事务。
   - 整个入口为同步调用，外包 try / finally；finally 无条件撤销授权，若仍在事务中则回滚。
   - 进程崩溃时闭包消失，未提交事务由 SQLite 回滚。
5. **完整性与静态检查：**
   - 入口开始前、结束后检查 U20 为空；
   - CI 限定删除模块的事务语句只在包装函数内。

**对应契约条款：** §10.3（同一事务内先写审计行再删，任一行删不掉整体回滚）；§1.2 与 ENG.1（防篡改限度）。

**表结构影响：** 新增 U20 deletion_txn_marker（至多一行，CHECK(id = 1)）；各受保护表的 DELETE 触发器、配置回收触发器、Branch UPDATE 触发器、branch_event INSERT 触发器改用三参数的授权函数。

**测试影响：** 新增 DB-D-25～30、35、37、38；DB-D-05 改写（xs_del_audit 作废，改按 U20 比对）；第 5.9 节正向用例补断言（G、W 不同时 armed，结束后 U20 为空、连接不在事务中）。

## R2　审计写入授权

**审核意见：** 第 (5) 条用了未注册的 xs_del_audit_writer()；成功审计写在授权之前，与“审计写入须授权”矛盾。须区分审计写入与删除权限，分别处理成功与失败审计，审计 ID 与本次删除绑定，普通路径不得伪造。

**修改位置：** 第 3.6 节第 (1)、(4)、(5)、(7) 条；第 5.9 节新增测试。

**修改内容：**

1. **注册函数：** 定为 xs_del_gate、xs_del_gc、xs_audit_write 三个；xs_del_audit()、xs_del_audit_writer() 作废。
2. **两种授权：** 审计写入授权 W（kind、audit_id、txn_token）与删除授权 G 分开，二者互斥。
3. **成功流程：**
   - begin() 写 U20（kind = success）；
   - arm W → 写成功审计与计数 → 撤销 W；
   - arm G → 置空 Branch、删除级联、回收配置；
   - commit()（先撤销 G）。
   - 审计写在删除之前，但经 W 授权，矛盾消除。
4. **失败流程：**
   - rollback() 撤销全部授权并回滚，成功审计一并消失；
   - 另起事务，新 audit_id′ 与新 txn_token′，U20 kind = failure；
   - arm W(failure) → 只写 success = 0 的审计、不写计数 → 撤销 W → commit()；
   - 失败审计本身再失败则不重试，向调用方报告。
5. **绑定：**
   - deletion_audit 的 INSERT 要求 xs_audit_write 返回 1，且 NEW.audit_id 等于 U20 audit_id，kind 与 success 相符；
   - deletion_audit_count 的 INSERT 要求所属审计行 success = 1。
6. **普通路径伪造：** 未持闭包，W 不会 armed；自写 U20 不知 txn_token；G armed 时插审计也因 W 未 armed 被拒。

**对应契约条款：** §10.3（先写审计行再删）；§10.4（最小删除审计：可保留与不得保留的字段；“是否完整成功”）。

**表结构影响：** U18 的 INSERT 触发器改用 xs_audit_write；计数表加“所属审计须 success = 1”。字段不变。

**测试影响：** 新增 DB-D-31～34、36；DB-D-19（删除模块之外插入审计被拒）保留。
