# evidence_link 数据版本缺口：核查结论与最小模型修复方案（待用户批准，未实施）

- 依据：用户 2026-11-21 对 E2-FIX-2 的答复第 4 条第 2 项。
- 状态：**方案，未实施。** 用户批准前不改 DDL。所涉表属 v1.0.6 修订单（draft，未获批准）的证据—主张模型。

## 一、核查结论：现有版本记录不能还原链接的首次加入时间与历史状态

1. claim、evidence_link、evidence_link_role（以及 text_variant_evidence、search_record、citation_record）都没有 data_release 列，也没有时间戳；正式库只追加，行一经写入不可改删，但写入时属于哪个数据版本不留痕迹。引擎测试 `4b 核查` 构造两个世界：同一链接分别在最早、最晚数据版本之后写入，库内可见内容逐字相同。
2. 计算快照的 snapshot_dependency 只记录计算所用变体、证据等依赖的三元组，不记录证据—主张链接；用户库快照不能反推正式库链接何时出现。
3. 正式库没有按数据版本导出的版本快照（E2 只有内存隔离库）。
4. 结论：链接的首次加入版本无法还原；“截至某版本有哪些支持关系”也无法还原。Q-F-24d 现按证据、变体两边的状态历史逐版比对，但链接本身只能按“当前存在”处理——若链接是后来才加入的，历史版本的比对会把它算进去（可能误报，不会漏报）。

## 二、最小修复方案

1. 上述六张表各增 `data_release TEXT NOT NULL REFERENCES data_release(data_release)`；写入触发器要求它等于当前最新数据版本（release_seq 最大者），不得回填旧版本。
2. 只追加表无法删除链接，历史状态需要“撤回”记录：新增 `evidence_link_retraction(evidence_id, claim_id, role 可空 = 整条链接撤回, data_release, reason, sequence_no UNIQUE)`。截至版本 R 的有效支持关系 = 写入版本 ≤ R、且没有 ≤ R 的撤回。
3. v_ri4_support 取“当前有效”；Q-F-24d 改为对每个版本取“截至该版本有效”的链接。
4. 迁移：正式库无数据；测试夹具与基准行补列。
5. 不在本方案内：主张细化到变体（【用户裁决 E2-FIX-2-R3】已登记为已知限制，另行报批）。
